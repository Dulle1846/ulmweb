# 3.8.0 — HUD 3.8: The Throne Room

**Status:** Production release on `ulmweb-branch`; Cloudflare Pages delivery is checked separately from CI.
**Scope:** Presentation only. No simulation rules, save schema, card values or economy balance changed.

## Why this increment exists

The previous in-game shell mixed three visual generations: a dark prototype HUD, a parchment card dock and a legacy canvas overlay. Visible consequences were clipped navigation labels, an empty hand panel that still advertised PLAY, a minimap sitting on top of the hand, a build-cancel control that stayed visible outside build mode, and raw floating-point income values in the resource strip. The world itself read as a flat green field with rectangular roofs.

This increment rebuilds the in-game layout as one deliberate royal interface, and raises the world rendering to match it, without touching gameplay.

## Delivered

### Layout

- Two-row banner header: identity plate, realm calendar, morale, player seal, five-resource ledger with live deltas, and a full-width command bar.
- Administration rail widened to 96 px; every visible label fits, a `DOMAIN` divider groups the sections and the rail scrolls vertically on short screens.
- World stage framed with a grain/vignette layer and a compass ornament. The duplicated canvas zoom chip is removed; the real HTML zoom controls remain the single source of truth.
- Right-hand administration panel keeps the parchment card inspector, event tabs and footer, restyled to the timber/parchment palette.

### Hand and cards

- Five explicit slots, numbered I–V, with dashed empty states.
- The dock is 820 px wide, anchored bottom-centre, and never overlaps the minimap, which sits directly above it.
- Card names wrap to two lines with a clamp; the rarity pill is no longer clipped.
- The selected-card inspector shows a real empty state (`NO CARD SELECTED`, explanation) instead of a PLAY ribbon over an empty frame.
- Selected card art now comes from `assets/royal-card-atlas.svg`, removing the last emoji from the card surface.

### Economy read-outs

- Every resource chip carries a rounded per-tick delta with positive/negative colour.
- Store cards reuse the same rounded formatter; `1.3333333333333286` is no longer possible in the HUD.
- Population mirrors capacity (`9 / 12`) in the top strip.

### Founding screen

- At desktop sizes the founding plate becomes two columns: title, illustration and pitch on the left, profile, seed, World Forge and actions on the right.
- The World Forge sliders use a two-column grid, so the whole screen fits without inner scrolling at 1440×900.

### World rendering

- Terrain prerender now computes a north-west hillshade from the height map, a coastal light strip, water depth tone, broad deterministic mottling and micro variation.
- Grass tufts and flowers are jittered inside their tile, translucent and curved, instead of a repeated `V` glyph.
- Roof art per building type: crenellated castle plan with courtyard, corner towers and banner for the keep; gable ridge, chimney smoke, tavern sign and barracks shield; farm furrows; log stacks; quarry pit; gold flecks; temple cross plan with gold rosette; tower merlons; wall walkway; rotating mill sails; wonder star; barrel hoops.
- Detail fades out with footprint size, so small structures stay readable instead of turning into noise.

### Correctness

- `.hidden` is now a global display contract. Previously only a few specific selectors honoured it, which is why `EXIT BUILD` stayed visible outside build mode.
- `income()` rounds and formats flow values, so the formatter cannot emit raw floating point.

- Live Chromium session against the local static build: start screen rendered, a realm was founded, the simulation ran to tick 96 at 4× speed, cards were drawn into the hand, and the card inspector switched from the empty state to the selected card.

## Explicit limits

- This is a layout and rendering increment. It does not add new management screens, cloud accounts, autosave, new card content or new economy systems.
- The legacy stylesheets remain loaded beneath `css/hud-v3.css` for backward compatibility rather than being deleted.
- Canvas art is procedural. There are no raster sprites, external fonts or runtime image requests.
- Screenshots in the audit are review evidence, not automated visual-regression baselines.
- The Cloudflare Pages deployment is a separate fact from CI. It was verified after the merge: the canonical address https://kings-and-cards.pages.dev/ serves the new layer and the live session described above produced no errors.
