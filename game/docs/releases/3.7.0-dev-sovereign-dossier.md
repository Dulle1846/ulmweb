# 3.7.0-dev — Sovereign dossier increment

**Status:** Development work; not a production release.  
**Target:** `ulmweb-branch` through a reviewed pull request.  
**Scope:** Presentation only. No simulation rules or save schema are changed.

## Delivered in this increment

- The living sovereign's existing character dossier now includes a dedicated royal-house section.
- The section reads the authoritative `getRoyalHouse()` model for the current consort, designated heir, living royal children and recorded royal-house history.
- Consort, heir and child entries reuse the existing dossier navigation event; they do not create a second person registry.
- The royal chronicle is capped at the latest eight recorded entries to keep rendering bounded.
- Former sovereign memorials are clearly distinguished from the current living sovereign. They do not display the successor's current consort/heir data as if it belonged to the deceased ruler.
- Added a locally bundled stylesheet with responsive layout and reduced-motion handling.
- Added static contract tests for data provenance, navigation, former-sovereign separation and bounded history.

## Explicit limitations

- The current royal model does not expose a coronation date, reign length, royal titles beyond the sovereign role, or a full legal succession law. The dossier therefore does not invent those values.
- The royal chronicle reflects the royal-house history array, which is bounded by the simulation to 48 entries.
- This increment does not complete the full interactive ancestor/descendant graph or all remaining responsive audits.
- Browser E2E must still exercise the sovereign-to-heir dossier hand-off on the exact PR head before merge.
